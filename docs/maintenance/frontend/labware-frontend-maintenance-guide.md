# Labware frontend maintenance

Labware uses the shared spatial page layout and sidebar sections. It has two independent workspaces: Tip tracking and Cytomat. Browsing a position does not write anything. Changes are sent only with Save changes, or the existing confirmed Reset family action.

## Files

- `pages/LabwarePage.tsx`: authorized route and retained section panels.
- `components/labware/TipTrackingPanel.tsx`: family/rack selection, drafts, per-family Undo history and writes.
- `components/labware/TipDeckOverview.tsx`: fixed Col A/Col B rack overview, in backend order.
- `components/labware/TipRackEditor.tsx`: adaptive rack grid, status selection, pointer/keyboard bulk selection and preview.
- `components/labware/CytomatPanel.tsx`: physical shelf stack and inline plate assignments.
- `components/labware/useLabwareSnapshot.ts`: snapshot reading and draft protection using the existing serial polling hook.
- `components/labware/useLabwareWorkspace.ts`: available width and remaining viewport height, independent of fitted child geometry.
- `services/labwareApi.ts`: unchanged request/response types and endpoints.

## Tip tracking

Choose a family, then a rack on the deck. Col A and Col B stay side by side, including on a 320px phone. Render `left_racks` and `right_racks` exactly in backend order: those arrays encode placement, and some IDs are deliberately not sorted numerically. Every rack shows a compact 8×12 status pattern. Its whole card is a labelled button; miniature dots are not tiny interactive targets.

Desktop uses a 40/60 deck/editor split when the editor can fit twelve 44px targets plus gaps and padding. At intermediate widths the overview gives space back to the editor while keeping at least 320px. Below the combined minimum, tapping a rack opens the full-screen dialog. Back restores focus to the selected rack. The dialog keeps Back and Save in its header; family/Refresh/Reset stay on the deck. Rack/tip selections, chosen status and drafts live in the parent, so resizing or switching families does not lose them.

The heading, toolbar and workspace use the full available page width. Both panes share header, diagram and footer tracks, so five overview rows align with the eight-row editor. Horizontal and vertical cell spacing adapt independently; dots stay circular using the smaller dimension, and editor targets remain at least 44px. The former workspace, overview and cell ceilings are removed. The shared measurement hook uses the outer anchor width/document position and available viewport height, observes preceding headers/actions, ignores ordinary scrolling, and does not use fitted child sizes as input. Equal measurements do not update state. Actual container resizing cancels unfinished selection while preserving completed drafts; small screens scroll instead of shrinking targets.

The shared rows use CSS subgrid. Do not add layout containment (including `container-type: inline-size`) to either subgrid pane: that prevents row sharing. Query containers belong inside the diagrams. Rack buttons explicitly stretch their grid children; Material UI's default centered alignment otherwise leaves miniature maps at their minimum size. Geometry checks compare content coordinates when scrolling is expected, while also checking that the workspace itself has not moved.

Both maps preserve column-major numbering: tip 1 is at the first row/column; tip 8 is the bottom of that column for an eight-row rack. The enlarged map uses labelled buttons and local horizontal scrolling on phones. Arrow keys navigate without editing, including at column edges; Enter/Space activates. No status is selected initially, so normal inspection does not edit. The Set tips to selector chooses the target status, and Set entire rack is the only separate bulk command. Navigation never changes the chosen status. Status dots retain their color when selected; borders, text and unsaved asterisks provide other cues. Ordinary wells have transparent borders. Rack buttons and wells disable ripple animation and use a static visible keyboard outline.

There is one selection interaction: drag a block, or choose its first and opposite corners with two clicks/taps/keyboard activations. Choosing the same tip twice changes one tip. A first activation only previews; the second commits one draft operation. Mouse/pen dragging previews the inclusive row/column range and commits at pointer-up. The reserved selection strip stays below the grid so feedback cannot move hit-test coordinates. Touch scrolling uses normal browser panning/pinch behavior; `touch-action: manipulation` prevents a double-tap zoom from swallowing a same-tip selection. Native touch scrolling preserves an already chosen corner, allowing the second corner to be offscreen initially. Its pointercancel only suppresses the scroll's click; canceled mouse/pen drags still clear their preview. Escape, Cancel selection, off-rack release and context changes also cancel. Pointer capture uses actual hit-testing for the endpoint; the compatibility click after a drag is suppressed once. A fresh pointer press or keyboard activation must not be swallowed. There are no separate paint/rectangle modes or row/column/range commands.

`pending` is keyed by family and a JSON `[rack, position]` key. Returning to the saved status removes that draft. Each Undo entry stores affected keys' previous draft values, including absence; this restores earlier unsaved work exactly. Undo affects the selected family. Save, Discard and Reset clear obsolete history. Save changes submits the selected family's drafts; other families retain their drafts and show a pending count.

Save captures the family and submitted edits before awaiting the PUT. A synchronous busy guard prevents duplicate submissions; mutation controls and family changes are disabled. Success patches the displayed snapshot, removes only submitted entries that still match, and resumes reading when no drafts remain. Failure retains drafts with an error. Discard affects the current family only. Reset family lives in More, requires the original confirmation, and is disabled while any drafts or writes are pending.

## Cytomat

The operator-confirmed layout is a vertical stack: exact position IDs 1–7 run from top to bottom. Positions 8 and 9 remain visible as Unused and cannot be edited. If an unused position has a saved plate, show it so the mismatch remains visible. The heading, actions and register use the full available width. At least 900px wide and 480px of remaining height enables a fixed-height workspace with one scrolling register body; compact/short windows use page flow. Nine base rows divide the body height equally with a 48px minimum and 44px Edit targets. A CSS size container supplies row sizing independently of row output. The inline editor and long values may grow without shrinking other rows. Other positions remain below 9 and have a visible shortcut. Local row text scales from 14 to 22px; there is no whole-page transform or zoom. Edit opens one inline Plate selector; Done or Escape closes it and restores focus to the row action. Opening an editor pauses reads before any value changes; closing without drafts resumes them.

Missing rows show Unavailable; only a confirmed empty plate string means Empty. Duplicate position IDs produce one unavailable row without an editor, while unaffected positions remain usable. Unexpected raw IDs, including 01, appear under Other positions with their original names; never silently alias them to numbered shelves.

Empty is a valid pending value; use property presence or nullish fallback, never a truthiness check. The selector uses `displayEmpty` and a render label so an empty string visibly reads Empty. Save submits all pending positions. A failed save retains them. The selector, row actions and Discard are disabled during Save. A failed save preserves the open editor and drafts.

## Permissions, reading and errors

`permissions.can_update` is authoritative for displaying editors. Read-only sessions keep lists, maps and selection but do not show mutation controls. Backend permissions still enforce each write.

Serial polling performs one read at a time. Background reads use Updating… in reserved caption space and keep controls usable; do not insert a progress bar above the grid or disable a focused Refresh button. Call useLabwareSnapshot.suspend() synchronously before entering a selection, editor or write state, so an already unfinished response cannot replace data before the pause effect runs. Only suspend for an action that enters a paused state; an unchanged Set entire rack operation must leave polling running. Inactive sections, pending edits in **any** family, writes, and unfinished selection gestures pause polling and invalidate late results. Save/Reset stay disabled while a selection is unfinished. Existing browser-tab visibility behavior is preserved. A successful response replaces the snapshot only while reading is enabled. Each panel validates the collections and permissions it renders; malformed payloads show an unavailable error instead of crashing or claiming the inventory is empty. The last good data remains after read failures and is explicitly labelled. Initial failures show Error + Retry before any empty state; empty means a successful response actually had no entries.

SectionPanel retains drafts and selection when switching Labware sections. Back, resizing and appearance changes do not recreate the workspace. Reload/close warns while drafts or writes exist. Drafts are not stored in browser storage and are not shared across logins. Leaving the Labware route unmounts its local state; this is not cross-route draft persistence.

## Repeatable browser checks

Failure cases are listed at the top of `labware.spec.ts` (editing and saving), `labware-layout-stability.spec.ts` (sizing and background reads) and `cytomat-spatial.spec.ts`. Run `npx playwright test labware-layout-stability.spec.ts labware.spec.ts cytomat-spatial.spec.ts` from `frontend` after a build. Tests intercept Labware GET/PUT endpoints with synthetic snapshots, so no robot data changes. Full 5+5 deck fixtures use long real rack IDs and all seven backend states. Layout screenshots cover 3840×2160, 1920×1080, 1366×768, 1280×720, 1024×768/600 and 390/320px phones, plus 1920 CSS pixels at 2× device scale and dark appearance. Checks cover full-width sizing, adaptive 40/60 proportions, shared diagram bounds, circular dots and height fit, keyboard geometry, bulk commit/cancel/Undo, real touch scrolling/two-corner input, delayed/failed saves, polling pause, subsection retention, reload warnings, error recovery, malformed responses and read-only permissions. Screenshots and traces are retained in `test-output/viewer-verification`. For native browser zoom, run `node frontend/e2e/labware-native-zoom.cjs` from the repository root and set its dedicated Edge window to 200%; the helper records native viewport/DPI evidence, interactions, screenshots and a trace, then cleans up.

The deck plus focused-rack design follows the same spatial-context principle as [Opentrons deck visualization and slot spotlights](https://docs.opentrons.com/flex/opentrons-app/protocol-viz/). Two-corner touch and keyboard alternatives to dragging follow [W3C dragging-movement guidance](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements).
